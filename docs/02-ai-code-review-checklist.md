# AI 生成代码审查清单

AI 可以先做一轮机械检查，但最终合并仍需要熟悉业务和系统边界的人负责。

配套阅读：[AI 生成代码验收清单](https://codex-inc.cn/insights/ai-generated-code-acceptance-checklist/)。官网文章从上线验收角度补充部署、回滚、安全和交接检查；本文件聚焦代码审查与合并前检查。

## 先确认改动范围

- [ ] 这次改动对应哪个业务目标或缺陷？
- [ ] 变更是否超出任务范围？
- [ ] 是否产生了重复组件、重复接口或不必要的新依赖？
- [ ] 是否修改了数据库结构、权限、日志或外部接口？
- [ ] 是否能用一个小提交回滚？

## 业务逻辑

- [ ] 正常流程符合需求和验收条件。
- [ ] 状态流转不能跳过必须的审批或确认。
- [ ] 重复请求不会重复扣款、创建记录或发送通知。
- [ ] 时间、金额、数量和时区的计算有明确规则。
- [ ] 错误提示不会掩盖真实失败，也不会泄露敏感信息。

## 权限与数据

- [ ] 每个读取和写入操作都检查当前用户的权限。
- [ ] 用户不能通过修改 ID、路径或请求体访问其他组织的数据。
- [ ] 管理员权限没有被前端条件判断单独保护。
- [ ] 日志、错误信息和测试数据没有包含真实密钥或隐私数据。
- [ ] 数据导入、导出、删除和迁移有恢复或审计办法。

## 工程质量

- [ ] 代码结构符合当前项目的模块边界和命名习惯。
- [ ] 异步任务、网络请求和数据库操作有超时与失败处理。
- [ ] 资源会被正确关闭，不会因为重试产生泄漏。
- [ ] 新增测试覆盖主要成功路径和至少一个失败路径。
- [ ] CI、构建和静态检查全部通过。
